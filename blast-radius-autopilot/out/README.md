# `out/` — captured runs and generated artifacts

Everything here was produced by running the tool; nothing is hand-written. The directory
accumulated across build tasks (B14 → B18), so some files carry **older impact semantics** than
the current code. Rather than delete the history, every stale file is marked in place:

- `.md` / `.txt` artifacts start with a **`⚠️ SUPERSEDED / HISTORICAL ARTIFACT`** banner naming
  what replaced them.
- `.json` artifacts (where a banner would break parsing) have a sibling
  `<name>.SUPERSEDED.txt`.

If a file has no marker, it was generated by the **current** code.

## A note on `written` in these artifacts

Since B19 the write-back counters split by **who authorised the write**:
`written (auto)` — a static verification returned PASS — and `written (human-approved by …)`
— a human approved a bound, single-use manifest. Any artifact showing a bare `N written`
predates B19 and is marked superseded.

## Where the Impact Assessment actually lives

Checked against the shipped aspect schema, not assumed:

```
InstitutionalMemoryMetadata fields = {url, description, createStamp, updateStamp, settings}
```

There is no document-body field, so DataHub OSS's `institutionalMemory` aspect cannot hold the
assessment text. What the write-back does instead:

- **into DataHub** — `blast_radius_*` structured properties (plus, on a human-approved write
  only, the six-field B20.3 approval audit: `_approved_by` / `_approved_at` / `_manifest_id` /
  `_verification_status_at_approval` / `_approved_writes` / `_approved_failures`),
  `pending-schema-change` and `impacted-by-upstream-change` tags, a one-line pending-change
  footer on `editableProperties.description`, and an institutional-memory **link**
  (url + title). The `blast_radius_writeback_*` keys are **report-only** and never reach the
  catalog — the emitted copy is built without write-back context on purpose;
- **into this directory** — the full assessment markdown as `ASSESSMENT-<change>.md`, which is
  exactly what that link points at.

The body is written before the link mutation is planned, so the link never dangles.
